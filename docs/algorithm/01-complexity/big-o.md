# 认识 Big O

> Big O 不精确计算程序需要几秒，而是描述输入变大时，工作量增长得有多快。

## 通俗实例：检查电影院门票

电影院只有一位检票员，每位观众都要检查一次：

| 观众数量 | 检查次数 |
| ---: | ---: |
| 10 | 10 |
| 100 | 100 |
| 1,000 | 1,000 |

观众数量变成十倍，工作量也约变成十倍，这种增长写成 `O(n)`。

## 常见增长速度

| 复杂度 | 通俗场景 | 输入翻倍后的大致变化 |
| --- | --- | --- |
| `O(1)` | 根据座位号直接找到座位 | 基本不变 |
| `O(log n)` | 每次排除电话簿的一半 | 增加很少 |
| `O(n)` | 给每位观众检票 | 约两倍 |
| `O(n log n)` | 高效整理一批卡片 | 略多于两倍 |
| `O(n²)` | 每个人与所有人握手比较 | 约四倍 |
| `O(2ⁿ)` | 每件物品都选或不选 | 指数增长 |
| `O(n!)` | 尝试所有排列 | 极快失控 |

## 为什么忽略常数

下面两段过程：

```text
遍历数组一次
```

```text
遍历数组两次
```

操作次数分别接近 `n` 和 `2n`。它们速度当然有差别，但增长趋势相同，所以都写作 `O(n)`。

Big O 关注的是规模增长趋势，不代表常数永远不重要。在真实工程中，两个 `O(n)` 算法仍可能有明显性能差异。

## 单层循环

::: code-group

```java [Java]
int sum = 0;
for (int number : numbers) {
    sum += number;
}
```

```python [Python]
total = 0
for number in numbers:
    total += number
```

```javascript [JavaScript]
let total = 0
for (const number of numbers) {
  total += number
}
```

```cpp [C++]
int sum = 0;
for (int number : numbers) {
    sum += number;
}
```

```go [Go]
sum := 0
for _, number := range numbers {
	sum += number
}
```

:::

数组长度是 `n`，循环执行 `n` 次，所以时间复杂度是 `O(n)`。

## 两层完整循环

```text
对每一个元素：
    再查看所有元素
```

外层执行 `n` 次，每一次内层也执行 `n` 次，总操作数接近：

```text
n × n = n²
```

所以是 `O(n²)`。

::: warning 看到两层循环不一定就是 O(n²)
如果两个指针都只会向前移动，每个元素总共只被处理有限次，即使代码看起来有嵌套循环，也可能仍是 `O(n)`。复杂度要计算总操作次数，不能只数缩进层数。
:::

## 二分为什么是 O(log n)

假设每次把范围减半：

```text
1024 → 512 → 256 → 128 → 64 → 32 → 16 → 8 → 4 → 2 → 1
```

只需要大约 10 次。因为 `2¹⁰ = 1024`，所以次数是 `log₂ n`，Big O 中写成 `O(log n)`。

## 空间复杂度

空间复杂度关注算法额外使用的内存：

- 只保存几个变量：`O(1)`；
- 创建一个长度为 `n` 的新数组：`O(n)`；
- 创建 `n × n` 矩阵：`O(n²)`；
- 递归深度为 `n`：调用栈可能占用 `O(n)`。

## 分析步骤

1. 确定输入规模 `n` 表示什么；
2. 找到随 `n` 增长的主要操作；
3. 计算操作总次数；
4. 保留最高阶增长项；
5. 单独分析额外空间；
6. 检查最好、平均和最坏情况是否不同。

## 自测

### 1. 读取数组第一个元素是什么复杂度？

<ExerciseSolution>

**答案：`O(1)`。** 无论数组有 10 个还是 100 万个元素，根据下标读取第一个元素都只做一次定位。`O(1)` 表示工作量不随输入规模增长，并不是“绝对只花 1 纳秒”。

</ExerciseSolution>

### 2. 遍历数组寻找最大值是什么复杂度？

<ExerciseSolution>

**答案：`O(n)`。** 最大值可能恰好在最后一个位置，因此最坏情况下必须查看全部 `n` 个元素。过程中只保存当前最大值，所以额外空间是 `O(1)`。

</ExerciseSolution>

### 3. 对有序数组进行二分查找是什么复杂度？

<ExerciseSolution>

**答案：`O(log n)`。** 每比较一次都能排除一半候选范围。若有 1,024 个元素，最多经过大约 10 次就能把范围缩小到一个元素，因为 `2¹⁰ = 1,024`。

</ExerciseSolution>

### 4. 枚举所有元素对是什么复杂度？

<ExerciseSolution>

**答案：`O(n²)`。** 第一个元素需要和其他元素配对，第二个元素也要继续配对，总次数是 `n(n - 1) / 2`。忽略常数和低阶项后得到 `O(n²)`。

</ExerciseSolution>

### 5. 生成所有子集是什么复杂度？

<ExerciseSolution>

**答案：至少是 `O(2ⁿ)`。** 每个元素都有“选择”和“不选择”两种决定，`n` 个元素组合出 `2ⁿ` 个子集。若还要把每个子集复制到结果中，严格计算通常是 `O(n · 2ⁿ)`。

</ExerciseSolution>
