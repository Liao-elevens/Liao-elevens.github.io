# 工程与海量数据算法

真实系统中的瓶颈不一定是 CPU。内存、磁盘 I/O、网络、缓存、并发和数据倾斜都会改变“最好算法”的含义。

## 工程专题

| 场景 | 常见算法与结构 |
| --- | --- |
| 数据无法全部进入内存 | 外部排序、多路归并、分块 |
| 文本搜索 | 倒排索引、分词、压缩 |
| 缓存 | LRU、LFU、ARC、一致性哈希 |
| 限流 | 计数器、滑动窗口、漏桶、令牌桶 |
| 去重 | 哈希、Bitmap、Bloom Filter |
| 热点统计 | Top K、Count-Min Sketch、Heavy Hitters |
| 流式处理 | 窗口、采样、在线聚合 |
| 分布式协调 | 一致性哈希、Quorum、向量时钟 |
| 数据库 | B+ 树、LSM Tree、连接与查询优化 |
| 压缩 | Huffman、LZ、Delta、Varint |
| 推荐与检索 | 倒排、向量近邻、图搜索 |

## 工程评价维度

除了 Big O，还要关注：

- 常数成本和缓存局部性；
- 顺序 I/O 与随机 I/O；
- 峰值内存；
- 延迟分位数；
- 数据倾斜；
- 并行扩展能力；
- 近似误差与故障恢复。
